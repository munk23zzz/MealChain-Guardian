Aritmetika silang: `923 + 19 = 942` dan `935 + 7 = 942` — tidak ada tes lama yang
hilang atau dilonggarkan.

**Sebabnya sudah diketahui dan bukan kode aplikasi.** `backend/tests/conftest.py`
punya fixture autouse `bersihkan_sisa_test` yang menyapu SEMUA user `%@test.local`
di AWAL dan AKHIR sesi pytest. Dua run bersamaan di DB demo yang sama saling
menghapus user fixture `auth_headers`/`monitor_headers` di tengah jalan, sehingga
puluhan tes menerima 401 pada token yang tadinya sah. Gejalanya khas: blok `F`
panjang berurutan, `{"detail":"token tidak valid"}`, `KeyError` pada kunci
respons (`routes`, `summary`), dan semuanya hijau saat berkasnya dijalankan sendiri.

**Kesimpulan yang jujur:** gerbang backend untuk keadaan W-3 **belum** terekam
sebagai satu run penuh 0-gagal, karena sesi lain menjalankan pytest berulang kali
pada DB yang sama. Yang bisa diklaim: (a) keadaan W-1+W-2 terekam bersih
(935/0), (b) 7 tes W-3 lolos berdiri sendiri maupun berpasangan dengan tes W-2
(12/12), (c) seluruh kegagalan run penuh terbukti polusi, bukan regresi.

## 3. Determinisme `tests/shipment-timeline.test.ts` (pertanyaan awal W-4)

Klaim "gerbang flaky karena waktu" **dibatalkan oleh bukti**:

- Fixture tes memakai stempel waktu ISO **tetap** (`2026-10-16T12:24:00+00:00`, `2026-11-07T11:00:00+00:00`);
  `grep -c "Date.now\|new Date(" tests/shipment-timeline.test.ts` → **0**.
- Modul yang diuji (`lib/shipment-timeline.ts`) murni: hanya mengurutkan
  `Date.parse(at)` dari data server, tidak membaca jam sistem.
- Run-1 yang merah terjadi karena berkas tesnya **disunting pukul 00:49:50 saat
  run dimulai 00:49:35** (mtime vs waktu mulai) — artefak suntingan bersamaan.
- Setelah itu suite frontend hijau berulang kali: **887/887** (17 Okt dini hari),
  **1080/1080** (setelah W-2), **1127/1127** (setelah W-3).

Karena tesnya **tidak** bergantung waktu, tidak ada perubahan kode yang dilakukan
untuk "menstabilkannya" — mengubah tes yang benar hanya akan menyembunyikan
penyebab sebenarnya. Yang dilakukan: memastikan setiap run dicatat bersama
keadaan repo saat itu (bagian 1–2).
